# 需求访谈报告：AI 行业日报站

- 日期：2026-11-01
- 方式：grill-with-docs（逐轮追问 + 当场落文档）
- 参与：用户 / 助手
- 结论：**7 个决策全部拍定，进入实施**

---

## 一、一句话结论

一个**纯静态**的 AI 行业日报站：每天 **12:00** 出完整版（15 条 + 中文 AI 摘要 + 重要度排序），**18:00** 出增量版（只放下午新增）。抓取与部署跑在 **GitHub Actions 云端**，不依赖用户电脑开机，不依赖 WorkBuddy 在跑；**零付费 API、零密钥、零后端**。

## 三、逐条决策与「被否方案」

### Q1 「不接 api」的边界

用户原话：**「核心要求就是不付费」**。

- ✅ 采纳：不付费为红线；不注册任何第三方服务、不填 key 作为附带约束。
- ✅ 推论：RSS / 公开网页 / agent 搜网均可用，因为没有一条需要付费或申请凭证。
- ❌ 否掉「只用浏览器能打开的页面、连 RSS 也不碰」：会砍掉最稳的取数路径。新闻站改版频率高，RSS 是最不容易被改版打断的接口形态。

### Q2 早上在哪看

用户答：**「都要」**（手机 + 电脑）。

- ✅ 采纳：必须有一个手机能打开的在线链接；同时本地保留可直接双击打开的完整副本。
- 影响：决定了必须有托管，而不能只做本地文件。→ 牵出 Q7。

### Q3 报表多简洁

用户答：**「15 条左右，但是重要的内容放在上面」**。

- ✅ 采纳：15 条上限；**按重要性降序，不按分类分组**（分组会把头条挤到下面）；每条带分类小标签但不做分组。
- ✅ 采纳：每条「中文标题 + 两句摘要（发生了什么 + 为什么重要）」。
- ✅ 默认（用户未反对）：前 3 条视觉加重，形成「今天最值得看」。
- ❌ 否掉 30+ 条的信息流形态：同质化严重，第三天就不会再打开。

### Q4 什么算 AI 新闻

用户答：**「可以」**（采纳推荐口径）。

- ✅ 采纳：① 大模型能力进展 ② 产品与应用 ③ 资本与公司 为主；④ 研究与论文只收「能上手的」（开源模型/工具库/方法）；⑤ 政策监管 ⑥ 硬件算力 只收大事件。
- 判据一句话：**「能不能影响你手上在做的东西」**。用户方向为科研数据处理与数字孪生，故工具/开源/方法优先于纯商业新闻。

### Q5 八点不准时怎么办

用户主动改需求：**「改成中午 12 点 + 晚上 6 点，因为中午 12 点绝大部分肯定开机了，就算没开机晚上 6 点也必定开机的」**。

- ✅ 采纳，且**顺带解决了一个用户没意识到的问题**：北京时间 12:00 对应美西前一天 20:00、美东 23:00，欧美一整个白天的新闻已落地；而 18:00 对应美东 05:00，欧美还在睡。
- ✅ 推论：**18:00 那期天然更薄**，硬凑 15 条必然注水 → 改为「增量版」，只放新增，没有就明说。

### Q6 额度成本

用户问：**「你每天自己写要花多少额度，我没那么多额度给你花呀」**。

实测后给结论（详见第四节）：

- ✅ 采纳档位 ②：**12:00 由 agent 写摘要，18:00 不跑 AI**。
- ✅ 关键技术决定：**原始 RSS 绝不进上下文**。7 个源原始 XML 约 11.6 万 token；脚本解析成候选池后约 1.85 万；再筛到 50 条约 0.5 万。**6.3 倍压缩，且第二刀之后只有 4% 的原始体积。**
- ✅ 诚实交代固定开销：每期约 **1.8 万 token 是系统提示与工具定义**，压不掉，只能靠少跑几次省 → 这正是 18:00 那期不跑 AI 的理由。
- ❌ 否掉档位 ③（两期都 AI）：月度成本翻倍，换来的是一个注水的晚间版。
- ❌ 否掉档位 ④（每期加搜索）：先跑两周看 ② 漏没漏，漏了再加，不预付最贵的那档。

### Q7 定时跑在哪、托管在哪

用户追问：**「我没打开 workbuddy 你也能自动跑么，而且会不会消耗我的性能」**。

查证结果：WorkBuddy 本地定时任务跑在客户端进程内（`LocalAutomationScheduler`），**客户端不启动就不执行**，错过 24 小时内启动可补跑，超过即跳过。

- ✅ 采纳 **B：GitHub Actions 云端定时 + GitHub Pages 发布**。
- ✅ 由此确定**三层解耦**（本次访谈最重要的结构性结论）：
  1. **地基层**（云端脚本，零 token）：抓取 → 去重 → 排序 → 生成页面。**电脑关机一周也照常更新。**
  2. **增强层**（WorkBuddy，每天 12:15）：只写中文摘要与重排序。没跑 → 页面照常，摘要位回落为原文标题。
  3. **阅读层**（Pages 静态页）：手机随时打开。
- ❌ 否掉 A（本地 Windows 计划任务 + Pages）：只是把「客户端得开着」换成「电脑得开着」，软肋没消失。
- ❌ 否掉 C（WorkBuddy 发布链接）：每次更新都依赖客户端，与「不用管它」的目标直接冲突。

## 五、架构定稿

```
GitHub Actions（云端，12:00 & 18:00）
   └─ digest 脚本：抓 RSS → 去重 → 评分 → 生成 issue JSON → 构建静态页 → 推 gh-pages

GitHub Pages（gh-pages 分支）
   └─ 手机 / 电脑打开同一个 URL

WorkBuddy（本机，12:15，可选）
   └─ 读候选池 → 写中文摘要 → 提交 summaries → 触发重建
      （没跑也不影响：页面照常，摘要位回落原文标题）
```

**降级策略**（任何一环挂掉都不出白屏）：

| 故障 | 表现 |
| --- | --- |
| 某个源挂了 | 少几条，页面照常 |
| AI 层没跑 | 无中文摘要，显示原文标题，排序按来源权重 |
| 全天抓不到内容 | 当期标「今日无更新」，不生成空壳 |
| `api.github.com` 抽风 | 那天缺摘要，次日自动补 |

## 六、遗留风险与观察项

1. **境外 runner 抓国内源**（量子位 / InfoQ）成功率未知，需第一周观察；失败会自动降级，不报错。
2. **GitHub Actions cron 有 5–20 分钟延迟**，实际更新时间可能晚于 12:00/18:00。
3. **工作日 arXiv 才有条目**，周末研究类条目自然为空，属正常。
4. **AI 摘要可能失真**，尤其涉及数字与表态 → 每条必须保留原文链接，页面上标注「摘要由 AI 改写」。
5. **仓库须公开**（免费账户 Pages 不支持私有仓库），代码与公开新闻数据均公开，无任何密钥。
6. **18:00 增量版在周末可能为 0 条**，页面需正面表达「今天没有新动静」，而不是显示空白。

## 七、验收标准

- [ ] 手机浏览器打开链接，3 秒内看到 15 条，一屏不溢出
- [ ] 每条都有：中文标题 / 摘要或原文标题 / 来源 / 时间 / 分类 / 原文链接
- [ ] 点过的条目刷新后仍为已读态
- [ ] 能翻看历史期次
- [ ] 删掉 AI 摘要后页面依然完整可读（降级验证）
- [ ] 电脑关机 24 小时后，网站仍有当天那一期（云端独立性的验证）
- [ ] 全程无任何 API key、无后端、无数据库
