# ADR 0002：定时与托管放在 GitHub Actions + Pages

- 状态：已采纳（2026-11-01 修订：18:00 档取消，只保留 12:00 一条 cron；其余不变）
- 日期：2026-11-01

## 背景

用户的两个前提：① 手机和电脑都要能读 → 必须有托管；② 电脑关机、WorkBuddy 没开也要更新 → 定时不能跑在本机。

本机实测网络：`api.github.com` 200 / 0.37s，`github.io` 200 / 0.8s，但 `github.com` 502 超时（`git clone/push` 不可用）。用户是 GitHub 免费账户，私有仓库不支持 Pages。

## 决策

- 定时：**GitHub Actions cron**（UTC `0 4 * * *` = 北京 12:00，一天一期）
- 托管：**GitHub Pages**，发布分支 `gh-pages`，内容 = 构建产物根目录
- 仓库公开；代码与新闻数据均无密钥

## 后果

- ✅ 完全脱离用户电脑：电脑关机一周，网站照常每天更新
- ✅ 零成本（公开仓库 Actions 不限量，Pages 免费）
- ✅ 主分支保持六区结构干净，构建产物只存在于 `gh-pages` 分支
- ⚠️ 仓库必须公开
- ⚠️ Actions cron 有 5–20 分钟延迟，不能依赖「12:00 整」
- ⚠️ 境外 runner 抓国内源（量子位 / InfoQ）成功率需观察；失败自动降级不报错（实测 9 源全通）
- ⚠️ 本机到 `github.com` 时通时断（502 / 000 都出现过），提交必须写成重试循环。
  修正：早期记录「不可达」不准确——`git push` 实际能用，只是不稳定

## 备选方案

- **本地 Windows 计划任务 + Pages**：被否。只是把「客户端得开着」换成「电脑得开着」，软肋没消失。
- **WorkBuddy 发布链接**：被否。每次更新依赖客户端，与目标直接冲突。
- **私有仓库 + 其它免费托管（Cloudflare Pages 等）**：暂不用。多一个账号就多一个「要注册服务」的违反项；若日后确实需要私密，再议。
