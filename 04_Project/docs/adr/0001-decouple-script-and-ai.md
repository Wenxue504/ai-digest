# ADR 0001：地基层与增强层解耦，AI 摘要可缺失

- 状态：已采纳
- 日期：2026-11-01

## 背景

用户要求「每天早上自动更新」。查证发现 WorkBuddy 的本地定时任务跑在客户端进程内（`LocalAutomationScheduler`），**客户端不启动就不执行**，错过 24 小时内可补跑，超过即跳过。若把「生成内容」整体交给 AI，那么客户端没开 = 网站空白。

同时，AI 写摘要的能力又确实优于纯规则排序，砍掉可惜。

## 决策

把系统拆成两层，**地基不依赖增强**：

- **地基层**：纯脚本抓取 → 去重 → 按来源权重与时间排序 → 生成完整页面。跑在云端，零 token。
- **增强层**：AI 读候选池，写中文摘要、重排序。跑在本机，**可能缺席**。

页面永远是「原文标题 + 来源 + 时间 + 链接 + 分类」的完整形态；摘要只是贴在标题下面的一层。AI 没跑，那层不出现，页面照常。

## 后果

- ✅ 客户端没开、电脑关机，网站依然每天更新
- ✅ AI 层可以随时关掉做对比实验，不影响可用性
- ⚠️ 需要维护两条产出路径，构建脚本必须能处理「summary 缺失」
- ⚠️ 无 AI 时英文源只有英文标题，中文可读性下降——这是刻意接受的代价

## 备选方案

- **全部交给 AI**：被否。可用性与「客户端是否运行」强绑定，而这恰恰是用户最担心的事。
- **定时任务搬到云端 WorkBuddy**：被否。云端沙箱读不到本机文件，且无法访问用户本地工程。
