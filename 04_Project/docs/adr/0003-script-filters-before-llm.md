# ADR 0003：原始 RSS 永不进入上下文，AI 只读「候选池」

- 状态：已采纳
- 日期：2026-11-01

## 背景

用户明确担心额度：「你每天自己写要花多少额度，我没那么多额度给你花呀」。

实测：7 个源原始 XML 共 186 KB ≈ **11.6 万 token**。一天两期就是 23 万 token/天、约 700 万/月——这确实会烧穿额度。而真正需要模型判断的，只是「这 50 条里哪 15 条重要，怎么用中文讲清」。

## 决策

**解析、去重、初筛全部由脚本完成，模型只看已经压扁的候选池。**

- 原始 XML：脚本读，模型不读
- 候选池：每条约 40 字（标题 + 摘要截断），50 条 ≈ 5000 token
- 模型输出：15 条 × 两句话 ≈ 1500 token

同时承认一笔压不掉的固定成本：每期约 **1.8 万 token 是系统提示与工具定义**。因此 18:00 的增量版**不跑 AI**——为 5–8 条薄增量付 1.8 万固定开销不划算，改由脚本直接生成。

## 后果

- ✅ 单期成本从 11.6 万降到 2.5 万（其中 72% 是压不掉的固定开销）
- ✅ 月度成本 ≈ 75 万 token（对比「两期都 AI」的 140 万）
- ⚠️ 脚本的排序质量决定了候选池的质量上限；关键词规则写差了，模型看到的就都是边角料
- ⚠️ 脚本无法理解语义，「重要的被筛掉」这类错误只能靠事后观察源清单来修

## 备选方案

- **直接喂原始 RSS**：被否，20 倍差价。
- **只抓 Top N 源的少量条目**：被否，会把覆盖面砍窄，且漏掉小源里的独家。
- **18:00 也跑 AI**：被否，见上。
