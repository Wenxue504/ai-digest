# ADR 0003：原始 RSS 永不进入上下文，AI 只读「候选池」

- 状态：已采纳（2026-11-01 修订：18:00 档取消，只保留 12:00 一期；月度成本随之降到约 38 万）
- 日期：2026-11-01

## 背景

用户明确担心额度：「你每天自己写要花多少额度，我没那么多额度给你花呀」。

实测：9 个源原始 XML 共 186 KB ≈ **11.6 万 token**。当时按一天两期估算是 23 万 token/天、
约 700 万/月——这确实会烧穿额度。而真正需要模型判断的，只是「这 50 条里哪 15 条重要，怎么用中文讲清」。

## 决策

**解析、去重、初筛全部由脚本完成，模型只看已经压扁的候选池。**

- 原始 XML：脚本读，模型不读
- 候选池：每条约 40 字（标题 + 摘要截断），50 条 ≈ 5000 token
- 模型输出：15 条 × 两句话 ≈ 1500 token

同时承认一笔压不掉的固定成本：每期约 **1.8 万 token 是系统提示与工具定义**。
这笔开销只能靠「少跑几次」省，压不下去——这也是后来取消 18:00 档的次要理由之一
（主因是那个时段欧美在睡觉，增量太薄）。

## 后果

- ✅ 单期成本从 11.6 万降到 2.5 万（其中约 72% 是压不掉的固定开销）
- ✅ 一天一期，月度成本 **≈ 38 万 token**
- ⚠️ 脚本的排序质量决定了候选池的质量上限；关键词规则写差了，模型看到的就都是边角料
- ⚠️ 脚本无法理解语义，「重要的被筛掉」这类错误只能靠事后观察源清单来修

## 备选方案

- **直接喂原始 RSS**：被否，20 倍差价。
- **只抓 Top N 源的少量条目**：被否，会把覆盖面砍窄，且漏掉小源里的独家。
- **每个时段都跑 AI**（v1 时的 18:00 档）：已取消，见 requirements v2。
