# 排序规则

> 改这张表必须和代码同一次提交改。代码：`04_Project/digest/rank.py`
> （2026-11-01 修订：此前本表与代码有三处数值不一致——HN/Ars 权重、时效加分、去重口径，已全部按代码校正。）

## 总分

```
score = 来源权重 + 时效加分 + 关键词加分 - 惩罚项
```

## 1. 来源权重

| 源 | 权重 | 理由 |
| --- | --- | --- |
| 量子位 qbitai | 1.0 | 中文 AI 垂媒，时效与密度最好 |
| DeepMind Blog | 1.0 | 一手官方，发一条是一条 |
| Google AI Blog | 1.0 | 同上 |
| InfoQ 中文 | 0.9 | 偏工程视角，质量稳 |
| MIT Tech Review | 0.9 | 深度报道 |
| TechCrunch AI | 0.9 | 资本与产品动态的最快信源 |
| The Verge AI | 0.8 | 偏消费向，偶有首发 |
| Hacker News | **0.55** | 信号强但噪音大。0.7 时一条刚发的边角帖能压过所有真新闻 |
| Ars Technica | **0.5** | 泛科技，命中率低 |

## 2. 时效加分

| 距发布时间 | 加分 |
| --- | --- |
| ≤ 6 小时 | **+2.0** |
| ≤ 12 小时 | **+1.5** |
| ≤ 24 小时 | **+1.0** |
| > 48 小时 | 直接丢弃 |

「现在」以构建时刻为准，固定 48 小时窗口。
（v1 曾给到 +3，结果刚发布的 HN 帖子稳居第一，已下调。）

## 3. 关键词加分

命中即加，可叠加，**每类最多加一次**：

| 主题 | 关键词 | 加分 |
| --- | --- | --- |
| 模型发布 | 发布 / 开源 / 上线 / release / launch / open-source | +1.5 |
| 头部厂商 | OpenAI / GPT / Gemini / Claude / DeepSeek / Qwen / 通义 / 豆包 / Llama | +1.2 |
| 资本 | 融资 / 收购 / 估值 / IPO / funding / acquire | +1.0 |
| 算力硬件 | 芯片 / GPU / 算力 / 数据中心 / TSMC / NVIDIA | +1.0 |
| 与本人相关 | Agent / RAG / 微调 / 评测 / benchmark / 数据集 / 论文 | +0.8 |

## 4. 惩罚项

| 情况 | 扣分 |
| --- | --- |
| 标题命中「招聘 / 直播预告 / 课程 / 折扣 / 广告 / sponsored / webinar」 | −3 |
| **拿到了摘要但不足 20 字**（信息量不足） | −1 |
| HN 条目且分数 < 100（噪音） | −2 |
| 泛科技源（HN / Ars / InfoQ）标题里没有 AI 词 | −1.5 |

**注意第二条的限定词**：完全不提供摘要的源**不扣分**。InfoQ 只给一句「点击查看原文>」，
按长度一律扣分会把整个源系统性地挤到后面——实测 48 条候选里有 17 条来自 TechCrunch，
正是这个原因。现在解析层已把这类占位文本归零，且空摘要不再受罚。

## 5. 分类判定

按顺序匹配，命中即停：

1. **资本**：融资 / 收购 / 估值 / IPO / 亿元 / 轮
2. **政策**：监管 / 法案 / 合规 / 诉讼 / 禁令 / 版权
3. **硬件**：芯片 / GPU / 算力 / 数据中心 / 晶圆
4. **研究**：论文 / arXiv / 基准 / 数据集 / 实验室 / 顶会
5. **模型**：发布 / 开源 / 参数 / 推理 / 训练 / 上下文
6. **产品**：兜底

## 6. 去重

同 URL 去重；标题归一化后**两两全局比较**，相似度 ≥ **0.78** 视为同一条，
保留来源权重高的那份。不是「只跟前 3 条比」。

## 7. 候选池只有一个生产者

候选池（`content/pools/<date>.json`）**只由云端 12:00 生成一次，并随仓库提交**。
本机 AI 层只读它、只写 `content/summaries/`，然后用 `--rerender` 把摘要盖回已有期次。

这是硬约束，不是优化项：早期本机也自己抓一遍，同一天的期次因此有两个生产者——
池一换，条目跟着换，内容不可复现，本节 §6「AI 只能重排、不能捞池外」的承诺也就没有实现基础。
