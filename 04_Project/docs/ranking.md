# 排序规则

> 改这张表必须和代码同一次提交改。代码：`04_Project/digest/rank.py`
> （2026-11-01 修订：此前本表与代码有三处数值不一致——HN/Ars 权重、时效加分、去重口径，已全部按代码校正。）

## 总分

```
score = 来源权重 + 时效加分 + 关键词加分 - 惩罚项
```

## 1. 来源权重

| 源 | 权重 | 理由 |
| --- | --- | --- |
| 量子位 qbitai | 1.0 | 中文 AI 垂媒，时效与密度最好 |
| DeepMind Blog | 1.0 | 一手官方，发一条是一条 |
| Google AI Blog | 1.0 | 同上 |
| InfoQ 中文 | 0.9 | 偏工程视角，质量稳 |
| MIT Tech Review | 0.9 | 深度报道 |
| TechCrunch AI | 0.9 | 资本与产品动态的最快信源 |
| The Verge AI | 0.8 | 偏消费向，偶有首发 |
| Hacker News | **0.55** | 信号强但噪音大。0.7 时一条刚发的边角帖能压过所有真新闻 |
| Ars Technica | **0.5** | 泛科技，命中率低 |

## 2. 时效加分

| 距发布时间 | 加分 |
| --- | --- |
| ≤ 6 小时 | **+2.0** |
| ≤ 12 小时 | **+1.5** |
| ≤ 24 小时 | **+1.0** |
| > 48 小时 | 直接丢弃 |

「现在」以构建时刻为准，固定 48 小时窗口。
（v1 曾给到 +3，结果刚发布的 HN 帖子稳居第一，已下调。）

## 3. 关键词加分

命中即加，可叠加，**每类最多加一次**：

| 主题 | 关键词 | 加分 |
| --- | --- | --- |
| 模型发布 | 发布 / 开源 / 上线 / release / launch / open-source | +1.5 |
| 头部厂商 | OpenAI / GPT / Gemini / Claude / DeepSeek / Qwen / 通义 / 豆包 / Llama | +1.2 |
| 资本 | 融资 / 收购 / 估值 / IPO / funding / acquire | +1.0 |
| 算力硬件 | 芯片 / GPU / 算力 / 数据中心 / TSMC / NVIDIA | +1.0 |
| 与本人相关 | Agent / RAG / 微调 / 评测 / benchmark / 数据集 / 论文 | +0.8 |

## 4. 惩罚项

| 情况 | 扣分 |
| --- | --- |
| 标题或摘要命中「招聘 / 直播预告 / 课程 / 折扣 / 广告 / sponsored / webinar」 | −3 |
| **没有摘要**（源只给标题） | **−0.3** |
| **有摘要但不足 20 字**（明显是残句） | −1.0 |
| HN 条目且分数 < 100（噪音） | −2 |

**为什么空摘要也罚一点点**：早先对空摘要免罚，结果没有任何正文的条目纯靠标题关键词
就能排上来（InfoQ 的「Agent Sandbox 为什么会成为新算力形态？」以 3.7 分进过前 15），
AI 拿到这种条目只能凭标题编两句。−0.3 表示「证据强度弱」，不是判它出局。

同时候选池里会给这类条目标 `"no_body": true`，让 AI 层知道只能依据标题、不得补事实。

**注意**：广告类关键词看的是 `title + summary` 两处，不只是标题。

## 5. 分类判定

按顺序匹配，命中即停：

1. **资本**：融资 / 收购 / 估值 / IPO / 亿元 / 轮
2. **政策**：监管 / 法案 / 合规 / 诉讼 / 禁令 / 版权
3. **硬件**：芯片 / GPU / 算力 / 数据中心 / 晶圆
4. **研究**：论文 / arXiv / 基准 / 数据集 / 实验室 / 顶会
5. **模型**：发布 / 开源 / 参数 / 推理 / 训练 / 上下文
6. **产品**：兜底

## 6. 相关性闸门（只对泛科技源生效）

量化位、DeepMind、Google AI 这类**专做 AI 的源不设闸门**，抓什么进什么。

HN / Ars Technica / InfoQ 是泛科技源，必须过闸门：**标题里必须命中 AI 词**（按词边界）。

为什么是标题而不是标题+摘要：「Show HN: 8-bit computer」的正文顺带提了一句 Claude，
按标题+摘要判就会过关，还能靠「模型」关键词拿 +1.2，稳进候选池。
**标题才代表这条新闻在讲什么**，正文里的顺带提及不算。

## 7. 去重

同 URL 去重；标题归一化后**两两全局比较**，相似度 ≥ **0.78** 视为同一条，
保留来源权重高的那份。不是「只跟前 3 条比」。

## 8. 候选池只有一个生产者，且不可覆盖

候选池（`content/pools/<date>.json`）**只由云端 12:00 生成一次，并随仓库提交**。
池文件一旦落盘，就是这一天的唯一事实——所有摘要的 id 都是照它写的。
因此再跑一次抓取会**沿用已有池、拒绝覆盖**（要覆盖必须显式 `--force-pool`）。

本机 AI 层读同一份池，用 **`--refresh`** 重新装配：它既要写摘要，也要**从 50 条里挑 15 条**。
`--rerender` 只把摘要盖到已有的 15 条上、不重选，所以**不能给 AI 层用**——
那样选条权就跑回关键词打分手里，ADR 0003 声明的「模型判断哪 15 条重要」就落空了。

两边读同一份池、跑同一套排序，所以内容可复现（同池两次 `--refresh`，items 哈希一致）。

这是硬约束，不是优化项：早期本机自己抓一遍，同一天因此有两个生产者——
池一换，条目跟着换，内容不可复现。
